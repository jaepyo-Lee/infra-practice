# Skill 업데이트 (update-skills)

현재 대화 컨텍스트를 분석해서 이 프로젝트의 스킬 파일들을 개선한다.

## 대상 파일

### 스킬 파일
- `.claude/commands/learn.md`
- `.claude/commands/tf-review.md`
- `.claude/commands/update-skills.md` (이 파일 자체도 대상)

### study 폴더 (항상 함께 업데이트)
- `study/terraform/*.md` — Terraform 개념 학습 파일
- `study/aws/*.md` — AWS 서비스 학습 파일
- `study/README.md`, `study/aws/README.md`, `study/terraform/README.md` — 인덱스

**`/update-skills`는 스킬 파일 업데이트와 study 폴더 업데이트를 함께 수행한다.**
대화에서 새로 다뤄진 개념, 교정된 오개념, Best Practice는 모두 study 파일에 기록한다.

### study 폴더 콘텐츠 분리 원칙

| 폴더 | 담는 내용 | 금지 |
|------|---------|------|
| `study/aws/` | AWS 서비스 개념, 동작 방식, CS 이론, 아키텍처 | Terraform 코드/설명 |
| `study/terraform/` | Terraform 언어, State, 모듈, 반복문, 함수 등 | AWS 서비스 상세 설명 |

- aws 파일에서 Terraform 내용이 필요하면 → `study/terraform/` 파일로 **링크**만 건다
- terraform 파일에서 AWS 내용이 필요하면 → `study/aws/` 파일로 **링크**만 건다
- 코드 예시는 `study/terraform/` 파일에만 작성한다

## 실행 절차

### 1. 기존 스킬 파일 읽기

모든 대상 파일을 읽어 현재 내용을 파악한다.

### 2. 대화 컨텍스트 분석

아래 신호를 기준으로 대화 전체를 분석한다.

#### 업데이트 트리거 (이런 게 발견되면 반드시 반영)

- **사용자 수정**: 스킬이 잘못 동작했을 때 사용자가 직접 교정한 내용
- **빠진 케이스**: 스킬이 커버하지 못한 질문/상황이 반복된 경우
- **새 규칙 합의**: 대화 중 "앞으로 이렇게 하자"고 명시적으로 정해진 것
- **오작동 패턴**: 스킬이 의도와 다르게 행동한 사례
- **엣지 케이스**: 기존 규칙이 모호해서 판단하기 어려웠던 경우

#### 업데이트 하지 않는 것

- 단발성 예외 (한 번만 일어난 특수한 상황)
- 아직 검증되지 않은 패턴 (추측에 의한 개선)
- 사용자가 명시적으로 언급하지 않은 개인적 판단

---

### 3. 변경 계획 수립

업데이트가 필요한 항목을 정리하고 사용자에게 먼저 보고한다:

```
## 발견된 개선 사항

### learn.md
- [추가] ...
- [수정] ...
- [삭제] ...

### tf-review.md
- [추가] ...
```

인수(ARGUMENTS)에 `confirm`, `바로`, `즉시`가 없으면 이 단계에서 멈추고 사용자 확인을 받는다.

---

### 4. 파일 업데이트

확인 후 실제 파일을 수정한다.

#### 수정 원칙

- **최소 변경**: 기존 내용은 최대한 보존하고, 꼭 필요한 부분만 수정한다
- **기존 구조 유지**: 섹션 순서, 형식, 헤딩 구조를 깨지 않는다
- **이유 명시**: 변경 내용 근거를 수정 요약에 반드시 남긴다
- **테스트 불가 변경 금지**: 동작을 검증할 수 없는 대규모 재설계는 하지 않는다

---

### 5. study 폴더 업데이트 (핵심 단계)

스킬 파일 업데이트와 **동시에** study 폴더를 직접 업데이트한다.
`/learn`을 별도로 호출하지 않고, 이 단계에서 직접 파일을 읽고 수정한다.

#### 업데이트 대상 식별

다음 내용이 대화에 등장했으면 study 파일에 기록한다:
- 새로 다뤄진 AWS 서비스 또는 Terraform 개념
- 사용자가 몰랐거나 교정된 오개념 (특히 기록 우선)
- Best Practice, 안티패턴, 컨벤션
- 에러 원인 분석 및 해결 방법

#### 실행 절차

1. 대화에서 기록할 주제 목록을 식별한다
2. 해당 `study/` 파일을 Read 툴로 읽어 현재 내용을 파악한다
3. 중복 없이 새 내용을 Edit/Write 툴로 직접 추가한다 (learn 스킬 호출 없이)
4. 새 파일 생성 시 README에도 항목을 추가한다

#### 판단 기준

- 이미 study 파일에 충분히 기록된 내용은 생략한다
- 단순 질의응답 수준이면 생략한다
- 판단이 애매하면 기록하는 쪽을 선택한다

### 6. 결과 요약 출력

```
## Skill 업데이트 완료

| 파일 | 변경 유형 | 내용 | 근거 |
|------|---------|------|------|
| learn.md | 추가 | ... | 대화 N번째에서 ... |

### 자동 기록된 학습 주제
| 주제 | 저장 위치 | 비고 |
|------|---------|------|
| VPC | study/aws/vpc.md | 기존 파일에 섹션 추가 |
| Terraform Module | study/terraform/modules.md | 신규 생성 |

### 변경하지 않은 항목 (이유 포함)
- ...

### 다음에 주목할 것
[이번에 반영하지 못했지만 주시해야 할 패턴]
```
