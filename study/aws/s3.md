## 1. 개념 설명

### S3가 뭔가

**S3 (Simple Storage Service)** 는 AWS의 객체(Object) 스토리지 서비스다.
파일 시스템처럼 경로를 쓰지만, 내부적으로는 **버킷(Bucket) + 키(Key) + 값(Value)** 구조로 동작한다.

```
s3://my-bucket/logs/2024/access.log
           └─────┘ └─────────────┘
          버킷명          키(경로)
```

### 블록 스토리지 vs 객체 스토리지

| 구분 | EBS (블록) | S3 (객체) |
|------|------------|-----------|
| 접근 | EC2에 마운트 | HTTP API |
| 구조 | 파일 시스템 | key-value |
| 크기 제한 | 볼륨 크기 | 객체당 5TB |
| 수정 | 부분 수정 가능 | 전체 재업로드 |
| HA | AZ 단위 | 자동 3개 AZ 복제 |

### 이 프로젝트에서 S3의 역할

| 용도 | Phase |
|------|-------|
| Terraform Remote State 저장 | bootstrap (이미 존재) |
| ALB Access Log 저장 | Phase 6 |
| CloudTrail 감사 로그 | Phase 6 |
| App 로그 저장 | Phase 6 |
| Static Assets (CloudFront 오리진) | Phase 3 (선택) |

## 2. S3 보안 계층 구조

S3의 접근 제어는 4개 레이어가 중첩된다:

```
인터넷
  │
  ├─ [1] Block Public Access      ← 버킷 레벨에서 퍼블릭 자체를 막음
  │
  ├─ [2] Bucket Policy            ← 누가, 어디서, 무엇을 할 수 있는지 (Resource 기반)
  │
  ├─ [3] IAM Policy               ← 누가 (Identity 기반)
  │
  └─ [4] VPC Endpoint Policy      ← VPC Endpoint 자체에도 정책 부착 가능
```

### Block Public Access

4가지 설정 전부 `true`로 설정하는 것이 기본이다.

| 설정 | 의미 |
|------|------|
| `block_public_acls` | 새 Public ACL 추가 차단 |
| `ignore_public_acls` | 기존 Public ACL 무시 |
| `block_public_policy` | Public 허용 버킷 정책 차단 |
| `restrict_public_buckets` | Public 버킷 정책 있어도 퍼블릭 접근 차단 |

> **실수 포인트**: 버킷 정책에서 `"Principal": "*"` 허용해도 Block Public Access가 켜져 있으면 차단된다. 정책만 믿으면 안 된다.

## 3. VPC Endpoint (Gateway 타입)

### 왜 필요한가

Private 서브넷의 EC2가 S3에 접근하려면 기본적으로 NAT Gateway를 거친다:

```
EC2 (Private) → NAT GW → 인터넷 → S3
```

이 구조의 문제:
1. **비용**: NAT Gateway 데이터 처리 비용 발생
2. **보안**: S3 트래픽이 인터넷을 경유

VPC Endpoint (Gateway)를 쓰면:

```
EC2 (Private) → VPC Endpoint → S3  (인터넷 경유 없음, AWS 내부망)
```

### Gateway vs Interface Endpoint

| 구분 | Gateway Endpoint | Interface Endpoint |
|------|------------------|--------------------|
| 지원 서비스 | S3, DynamoDB | 대부분의 AWS 서비스 |
| 비용 | **무료** | 시간당 + 데이터 요금 |
| 구현 방식 | Route Table에 경로 추가 | ENI (프라이빗 IP) 생성 |
| DNS 변경 | 없음 | 프라이빗 DNS 사용 가능 |

S3는 Gateway Endpoint가 있으므로 **반드시 Gateway 타입을 쓴다** (무료 + 더 단순).

### 동작 방식

Gateway Endpoint는 Route Table에 특수 경로를 추가한다:

```
목적지: pl-xxxxxxxx (S3 Prefix List)  →  vpce-xxxxxxxxx (Endpoint)
```

EC2가 S3 주소로 요청하면 Route Table이 이 경로를 보고 인터넷 대신 Endpoint로 보낸다.

> **핵심**: `route_table_ids`에 private subnet의 RT를 연결해야 EC2에서 실제로 사용된다. 빠뜨리면 NAT Gateway로 계속 나간다.

## 4. Terraform 핵심 파라미터

### `aws_s3_bucket`

| 인수 | 필수 | 설명 |
|------|------|------|
| `bucket` | 선택 | 버킷 이름 (전 세계 유일). 미지정 시 랜덤 생성 |
| `force_destroy` | 선택 | true면 객체가 있어도 버킷 삭제 허용. 기본 false |

> `force_destroy = true`는 실습 환경에서 편리하지만 운영에선 절대 쓰지 않는다.

### `aws_s3_bucket_public_access_block`

| 인수 | 필수 | 설명 |
|------|------|------|
| `bucket` | 필수 | 대상 버킷 ID |
| `block_public_acls` | 선택 | 새 Public ACL 차단 |
| `ignore_public_acls` | 선택 | 기존 Public ACL 무시 |
| `block_public_policy` | 선택 | Public 허용 정책 차단 |
| `restrict_public_buckets` | 선택 | Public 버킷 접근 차단 |

### `aws_s3_bucket_server_side_encryption_configuration`

S3 버킷에 SSE(서버 사이드 암호화)를 설정하는 리소스. tfsec HIGH 이슈 항목이다.

```hcl
resource "aws_s3_bucket_server_side_encryption_configuration" "example" {
  bucket = aws_s3_bucket.example.id

  rule {
    apply_server_side_encryption_by_default {
      sse_algorithm = "AES256"          # AWS 관리 키 (비용 없음) — 일반 권장
      # sse_algorithm     = "aws:kms"   # 고객 관리 KMS 키 (비용 발생, compliance 요구 시)
      # kms_master_key_id = aws_kms_key.s3.arn  # aws:kms 사용 시 필요
    }
  }
}
```

| sse_algorithm | 설명 | 비용 | 사용 시점 |
|---------------|------|------|---------|
| `AES256` | AWS 관리 키 (SSE-S3) | 없음 | 일반 서비스 |
| `aws:kms` | 고객 관리 KMS 키 | KMS 요금 발생 | 컴플라이언스, 감사 추적 필요 시 |

> tfsec은 CMK(고객 관리 키) 미사용도 별도로 잡지만, AES256으로도 암호화 자체는 충족된다. CMK는 compliance 요구사항이 있을 때만 적용한다.

### `aws_s3_bucket_policy`

```hcl
resource "aws_s3_bucket_policy" "example" {
  bucket = aws_s3_bucket.example.id
  policy = jsonencode({
    Version = "2012-10-17"
    Statement = [{
      Effect    = "Deny"
      Principal = "*"
      Action    = "s3:*"
      Resource  = [
        "arn:aws:s3:::${bucket_name}",
        "arn:aws:s3:::${bucket_name}/*"
      ]
      Condition = {
        StringNotEquals = {
          "aws:sourceVpce" = vpce_id
        }
      }
    }]
  })
}
```

> **Allow가 아닌 Deny + StringNotEquals 조합**을 써야 한다. "VPC Endpoint 아닌 것은 모두 거부"가 더 강력하다.

### `aws_vpc_endpoint` (Gateway 타입)

| 인수 | 필수 | 설명 |
|------|------|------|
| `vpc_id` | 필수 | 연결할 VPC ID |
| `service_name` | 필수 | `com.amazonaws.{region}.s3` 형식 |
| `vpc_endpoint_type` | 선택 | `"Gateway"` 또는 `"Interface"`. S3는 Gateway |
| `route_table_ids` | 선택 | Gateway 타입 전용. 연결할 Route Table ID 목록 |
